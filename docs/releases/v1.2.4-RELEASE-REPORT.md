## Production Changes

**P0 — app crashed on every single launch (PR #117, commit
`2fe793de`).** Found by following this project's own real-artifact-
validation requirement before tagging: built the actual release binary
and it crashed immediately on launch. `BrainManager::start_health_monitor`'s
`tokio::spawn` (`sidecar.rs`) was called from `start_brain()`, a plain
sync fn with no Tokio runtime active on the calling thread — every
launch hit `there is no reactor running, must be called from the context
of a Tokio 1.x runtime` inside tao's macOS app-delegate callback, a
non-unwinding panic that aborted the whole process. This would have
shipped to every user had the artifact not been built and launched
before tagging. Fixed by explicitly entering the runtime via
`tauri::async_runtime::spawn` before calling `start_health_monitor`, the
same pattern already used three lines above for `manager_clone.start()`.

**Everything from the unpublished v1.2.3 (PR #111/#115), carried forward
unchanged:**

- Dominant bug class (74 instances) — silent data-fetch failure
  rendered identically to "0, all healthy" across Workloads/Resources/
  Scaling/Admission/CRDs Overview, the Dashboard health-score widget,
  Intelligence Panel, Security assets, Pod status distribution, 4
  Dashboard widgets, 3 project dialogs, `clusterPresenceStore`.
- Backend panic recovery added to all 26 previously-unprotected
  goroutines (pod exec, shell streaming, port-forward, Fleet
  aggregation, metrics collection, topology rebuild).
- 2 real P1 resource leaks fixed: goroutine/exec-connection leak on pod
  exec/shell/kcli disconnect; HTTP connection leak on retried Artifact
  Hub requests.
- Cluster-switch race condition fix (`keepPreviousData` showed stale
  previous-cluster data unlabeled during a fetch after switching).
- CI fixes: `cosign-installer@v4`→`@v3` pin, `staticcheck SA1019`
  suppression, weekly security-scan workflow re-enabled after a silent
  60-day inactivity disable.
- Dead-code cleanup found during this PR's own lint gate:
  `shortestPath`/`buildFailurePath` removed, consolidated onto the
  already-adopted `bfsParents`/`pathFromParents` pattern, with tests
  rewritten to match (not deleted).
- Full adversarial security/concurrency audit: zero exploitable
  findings.
