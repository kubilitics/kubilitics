## Release Purpose

Consolidates the completed, tested, production-ready reliability engineering
work accumulated on `feat/stability` since the last genuinely published
release (`v1.2.0`). Per the project's permanent versioning policy
established this session, this is a **patch release** — no single item here
individually warrants a minor version bump, but the accumulated body of
work is substantial and coherent. Supersedes three earlier local-only,
never-published version artifacts (`v1.2.1`-old, `v1.2.2`, `v1.2.3`,
`v1.3.0`) created during an earlier, incorrect campaign-phase-per-version
strategy — all four were confirmed absent from both GitHub remotes via
`gh release list` and `git ls-remote --tags` before being deleted and
superseded by this consolidated release.

## Included Functionality

**Lifecycle** (`561929fa`): `ClusterLifecycleManager` — registered clusters
no longer eagerly start informers; first real consumer activation triggers
exactly one lazy generation; idle clusters release resources after a
10-minute TTL; reconnect/removal/re-registration produce clean state.
`EngineLifecycleManager` — same pattern for Blast Radius's `ClusterGraphEngine`,
plus BLASTRADIUS-1 (resource-topology reuses the running graph engine's
cache instead of re-listing live). VALID-02 (no unwanted reconnect on
`ResolveClusterID`), VALID-03 (password-reset token no longer logged in
plaintext). Fixed one data race found during this release's own validation
(see Known Issues Resolved below).

**Fleet** (`e9e69ee4`): single aggregate `/api/v1/fleet/overview` endpoint
replaces the previous 1+N request pattern; `Reachable` correctness fix
(every cluster previously read as unreachable regardless of actual state);
bounded concurrency (`errgroup.SetLimit(10)`) on both fan-out layers; failed
List calls tracked and surfaced instead of silently discarded.

**Topology** (`b35119c0`): storage N+1 fix (~105x speedup — PVC/PV
relationship inference was falling back to a live per-object `Get()` on
every Pending PVC forever under default client-go rate limits); shared
`maxNodes` default across V1/V2/gRPC; VALID-07 (V2 `force_refresh` now
genuinely rebuilds instead of silently serving the cache).

**Reliability/Bounded I/O** (`957b5b78`): PipelineManager no longer holds
its global lock during unbounded cluster-sizing I/O; `buildClusterSummary`
and `discovery.Manager.Refresh` both gained bounded internal timeouts;
CONTAM-1 (WebSocket broadcasts correctly isolated per-cluster, regression-
tested against leakage).

**UI** (`93d2ab47`): VALID-05 (Cluster Picker connect flow fixed for
non-default `KUBECONFIG` paths); shared, tested `k8sQuantity` resource-unit
parsing.

## Known Issues Resolved During This Release's Own Validation

**P1 — data race in `TestVALID02_ConcurrentClusterIsolation`.** Root cause:
`mockClusterRepoForValidation.List()` (a pre-existing test mock in
`validation_test.go`, used by several tests) returned the same
slice/pointers on every call. Production's real `SQLiteRepository.List()`
always deserializes fresh objects per call, so `ListClusters()`'s in-place
mutation (status/server-URL enrichment) is safe there — but the shared-pointer
mock created a genuine, detectable race when `valid02_test.go`'s new
concurrent test reused it. **Fixed**: the mock now returns a defensive copy.
Verified: `go test -race -run TestVALID02_ConcurrentClusterIsolation` went
from FAIL to PASS; full-suite re-run confirmed 0 races remain anywhere.

## Deferred to v1.2.2

- ~297 goroutines per registered cluster from eager informer startup on
  *registration* (not activation) — a real, quantified, architectural
  finding from `FLEET-PERFORMANCE-IMPLEMENTATION.md`, explicitly NOT part
  of this release. Needs its own dedicated investigation and approval.
- Two independent cluster-health computations (Fleet's simple thresholds
  vs. `/summary`'s healthscore engine) that can disagree on the same
  cluster at the same moment — documented, not unified.
- 7 exotic/computed resource-list sort keys remain O(N) (unchanged from the
  earlier resource-list pagination fix, low-impact, deliberately deferred).
- Multi-namespace resource-list merge path and `ListFromCache` (used by
  `/workloads`/`/events`) remain O(N).
- Sibling V2 topology force-refresh gap in `GetTopologyV2Traffic`/
  `GetCriticality` (same bug class as VALID-07, different endpoints).
- 20K+ scale campaign, browser/frontend performance validation, Headlamp
  comparative study — none started, all explicitly out of scope.
- Fleet summary caching (none exists on the Fleet path today, unlike
  `/summary`'s LRU cache) — documented gap, not fixed.
