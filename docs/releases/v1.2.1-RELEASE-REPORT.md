# Kubilitics v1.2.1

## Release Purpose

**RELEASE R1 — Resource List Scalability.** First mini-release of the restarted
Enterprise Scale & Reliability campaign under the new incremental release
strategy. Closes the single P1 found during 10K-scale infrastructure-attribution
testing before any further campaign work proceeds, per the campaign's new rule:
"every completed phase group must end in a tested, documented, stable, releasable
checkpoint."

## Included Changes

Scoped strictly to the resource-list pagination fix — no unrelated changes:

- `kubilitics-backend/internal/k8s/informer.go` — typed-object fast path for
  `ListFromCacheWithPagination`'s 3 most common sort keys (`name` default,
  `namespace`, `creationTimestamp`): filter+sort on `metav1.Object` accessors,
  convert only the returned page. Exotic/computed sort keys (`restarts`,
  `status.phase`, etc.) unchanged on the original path.
- `kubilitics-backend/internal/k8s/informer_pagination_fastpath_test.go` (new) —
  12 regression tests.
- `docs/RESOURCE-LIST-PAGINATION-N1-INVESTIGATION.md` (new) — full investigation
  record (Phases 1–11 per the original remediation protocol).
- `docs/ENTERPRISE-PERFORMANCE-CAMPAIGN.md` — `# PHASE 10K` section added
  (workload construction, infrastructure-attribution controls, this finding).
- `docs/ENTERPRISE-SCALE-RELIABILITY-REPORT.md` — `## 22.` section added.
- `docs/RELEASE-PROCESS-AUDIT.md` (new) — release-mechanism audit performed
  before this release, establishing `v1.2.0` as the actual stable baseline and
  `v1.2.1` as the next safe version.

**Explicitly NOT included**: the large body of pre-existing uncommitted work on
`feat/stability` from earlier campaign phases (Hybrid Informer Lifecycle,
PipelineManager, EngineLifecycleManager, VALID-01–07, CONTAM-1, Fleet N+1, Helm
PVC/StorageClass fallback already merged via `fix/helm-pvc-storageclass`) remains
uncommitted and untouched by this release, per the explicit instruction to
preserve it and not mix unrelated work into one release.

## Findings Closed

- **P1 — Resource-list pagination N+1**: `ListFromCacheWithPagination` converted
  and sorted the entire informer-cached collection on every request regardless of
  `limit`, causing 63–80% concurrent request failures at 10,792-pod scale.
  **FIXED.**

## Performance Evidence

Controlled, quiescence-verified, 5-trial methodology against the live 10,792-pod
`kubilitics-phase-e` lab cluster:

| Metric | Before | After | Improvement |
|---|---|---|---|
| `limit=100`, N=20, p50 | 25.81s | 0.034s | 759x |
| `limit=100`, N=20, CPU/trial | 119.0 CPU-sec | 0.35 CPU-sec | 337x |
| `limit=100`, N=20, failures | 63/100 | 0/100 | eliminated |
| `limit=5000`, N=20, p50 | 13.58s | 3.94s | 3.4x |
| `limit=5000`, N=20, CPU/trial | 126.9 CPU-sec | 20.4 CPU-sec | 6.2x |
| `limit=5000`, N=20, failures | 80/100 | 0/100 | eliminated |

In-process A/B (5,000 synthetic pods, temporary comparison, deleted after use):
old path 25.9ms vs. new path 1.4ms for a 100-item page — 18.8x faster, byte-identical
ordering.

## Live Validation

LIVE-REPRODUCED against the real lab cluster (not a unit-test mock): backend built
from this exact fix, run against `kubilitics-phase-e` (10,792 pods / 55 namespaces),
measured via direct HTTP requests at N=1/5/10/20 concurrency for both `limit=100`
and `limit=5000`, with quiescence verified via `process_cpu_seconds_total` delta
before each of 5 trials per N. Raw-kubectl infrastructure-attribution control run
at the same N values confirms the pre-fix failures were Kubilitics-side, not
inherited lab-infrastructure pressure.

Real `nightshift-dev` environment confirmed untouched throughout (exactly 20 pods,
checked before/after every test run).

## Regression Results

0 failures, 0 data races across the full backend `-race` suite. 0 regressions in
any explicitly re-run named suite (see Tests section). No frontend changes, so no
frontend regression surface.

## Known Limitations

- The GC-pressure explanation for the pre-fix concurrency amplification (observed
  15–28x CPU-seconds beyond naive linear scaling) is strongly evidenced via
  heap-delta data and single-request-cost arithmetic, but not independently
  proven via a live GC trace captured during an actual N=20 burst — a lab-tooling
  mechanical failure (not a backend defect) prevented that specific capture.
  **DOCUMENTED, not re-attempted for this release** — does not block the fix's
  correctness or the measured improvement, which are both independently verified.
- The 7 exotic/computed sort keys (`restarts`, `status.phase`, `status.podIP`,
  `spec.nodeName`, `spec.replicas`, `status.replicas`, `status.readyReplicas`)
  still pay the original O(N) cost — unchanged, not regressed, not improved.
  **DEFERRED** — not in scope for this release.
- The multi-namespace merge path (`?namespaces=a,b,c`) and `ListFromCache` (used by
  `/workloads` and `/events`) are unchanged by this fix. **DEFERRED.**

## Known Unfixed Risks

- No frontend typecheck gate exists in CI (`frontend-ci.yml` has no `tsc --noEmit`
  step) — **not relevant to this backend-only release**, but noted in
  `docs/RELEASE-PROCESS-AUDIT.md` for future frontend-touching releases.
- GitHub's automated release pipeline's CI-verification gate is soft (warns, does
  not block, if no CI check-runs exist for the tagged commit) — our local gate
  (this document) is the real safety net for this release.
